# Api Spec Store

> 拒绝随意写接口。集中管理 API 规范文档，通过强校验与流程门禁，让接口设计有章可循。

## 🎯 为什么需要这个项目？

在团队协作中，接口编写往往过于“随意”：字段命名混乱、缺少必填说明、响应结构不统一，导致前后端联调成本极高。

`api-spec-store` 不仅仅是一个接口文档存储库，更是一个**接口规范校验中心**。我们的目标是：**让规范代码化、让校验自动化**。

## 🛡️ 核心机制（四道关卡）

1. **录入即校验**：保存接口文档时，强制进行结构化校验（必填项、命名规范、统一响应体等），不合格直接拦截。
2. **提交卡门禁**：提供 CLI / Maven 插件接入 CI 流水线，接口规范不达标，代码合并不了。
3. **变更留痕与评审**：破坏性变更（删字段、改类型）强制走评审流，责任到人。
4. **代码与文档一致性**：自动化比对代码与 Spec 文档，解决“代码改了文档没改”的痛点。

## 🛠️ 技术栈

- **语言**: Java 17+
- **框架**: Spring Boot 3.x
- **规范标准**: OpenAPI 3.x
- **存储**: MySQL (JSON 字段存储 Schema)

## 📦 模块划分 (规划中)

- `spec-store-core`: 规范校验引擎（核心逻辑）
- `spec-store-web`: 对外 REST API 与管理后台
- `spec-store-client`: 业务方接入的 SDK 与 CLI 工具
